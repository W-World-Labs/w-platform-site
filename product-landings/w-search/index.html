Overview

W-Search

W-Search consolidates web, news, image, and corpus full-text search behind a single clean API — so products and developers stop managing multiple search provider integrations and get consistent, high-quality results from one endpoint. It can route queries to self-hosted search engines or external API providers based on your configuration, and supports indexed full-text search over private corpora alongside public web results. Any W Platform product that needs search capability plugs into W-Search and gets everything at once.

W
Multi-source results in one call

Multi-source results in one call

A single W-Search API request can return blended results from web indices, news feeds, image collections, and your own private corpus simultaneously. Response merging and deduplication happen server-side, so the caller receives a clean ranked list rather than having to fan out and reconcile multiple upstream responses.

MRI
Self-hosted and API engine support

Self-hosted and API engine support

W-Search supports both self-hosted search backends (SearXNG, Meilisearch, Elasticsearch) and external API providers, configurable per query type. This means you can keep sensitive corpus searches entirely on-premise while still routing general web queries to a public index — with the same API surface throughout.

SAA
Corpus full-text search

Corpus full-text search

Index your own documents, logs, knowledge bases, or product data and search them alongside live web results. W-Search handles tokenization, stemming, and relevance scoring, returning structured hits with excerpt highlights. Corpus indices are managed through the W-Search admin interface and accessible to any authorized W-ID client.
